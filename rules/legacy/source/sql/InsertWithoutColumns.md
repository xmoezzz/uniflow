## SQL注入漏洞描述

### 漏洞原理

在 SQL 语句中，通过 `set col = ...` 的方式插入一个新列，如果该列的名字不是 "col"，则会导致 SQL 语句执行失败。攻击者可以利用这一特点，在用户输入中插入恶意的列名，从而实现 SQL 注入攻击。

### 非合规代码示例

```sql
insert into tab values (1);
```

在这个示例中，攻击者没有指定要插入的列，而是直接在 `values` 后面插入了一个数字 `1`。由于 `tab` 表中没有名为 "values" 的列，这个语句会报错并停止执行。攻击者可以利用这种错误，进一步提交恶意 SQL 语句，导致数据库被篡改或数据泄露。

### 合规解决方案

为了防止 SQL 注入攻击，应该在插入数据时指定要插入的列名。可以使用以下方法来实现：

```sql
insert into tab (col) values (1);
```

在这个示例中，攻击者使用了 "col" 作为列名，而没有使用 "values"。这样，插入的数据将直接添加到 "col" 列中，而不是添加到 "values" 列中。这可以有效防止 SQL 注入攻击。
